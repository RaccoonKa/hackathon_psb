База знаний
- На диске (knowledge-base) лежат все данные для базы знаний.
- На public- и private-проверке используется одна и та же база знаний, различаются только вопросы.
- Базу знаний можно предобрабатывать в любой степени, ограничений на предобработку нет.
- Дополнять базу знаний нельзя; внешние источники использовать нельзя.
- Для тестирования разрешено использовать дополнительные источники, не входящие в предоставленную базу знаний, но при самом тесте используется только база знаний.
- В ZIP можно включать готовый поисковый или векторный индекс и вспомогательные файлы JSON/YAML, при условии что они не подключают внешние источники.

Техническая реализация, модели, инфраструктура
- Ограничение по времени — 20 минут на весь прогон; ограничений по количеству токенов на запрос пользователя нет.
- Строить решение можно на основе Knowledge Graph, ограничиваться только VectorDB не обязательно.
- Для генерации, эмбеддингов и реранкера ограничений нет (количество и параллельность запросов, размер контекста и батча).
- Доступная модель реранкера и точный формат её API описаны в sample submission.
- Модели для реранкинга и эмбеддинга подключаются через доступные на платформе модели (подробности — в sample submission).
- Предоставить собственные API-ключи к моделям нельзя.
- Ресурсы контейнера на платформе: 4 ГБ CPU, 16 ГБ RAM, лимит времени — 20 минут на прогон.
- Свои модели, в том числе zero-shot, использовать нельзя — только доступные на платформе.

Сабмиты, автоматическая проверка и критерии
- Механика сабмитов похожа на Kaggle.
- Каждый участник команды может самостоятельно разработать решение и отправить его на автоматическую оценку, чтобы сравнить результаты и объединить лучшие подходы в финальном решении.
- Ограничения на количество сабмитов от команды нет.
- В лидерборде учитывается лучший из всех попыток результат.
- Способ выполнения кейса («вайбкодинг» или своими силами) не важен — главное, чтобы решение выполняло требования.
- Корректные ответы оцениваются, даже если часть вопросов обработается с ошибкой.
- Время ответа на скор LLM-судьи не влияет.
- По отдельным вопросам логи и оценки недоступны — команде виден только общий балл.
- Длина ответа судьёй не учитывается: оценка не снижается, если ответ длиннее рекомендованных 150 слов.
- Если бот задаёт уточняющий вопрос в одиночном тест-кейсе, где вопрос полноценный, это трактуется как недостаточный ответ; если запрос неполный, уточнение допустимо, но лучше сразу выводить основную трактовку.
- Baseline совпадает со стартером.

Дизайн и веб-прототип
- Ограничений по цветам дизайна нет.
- Можно добавлять в интерфейс другие экраны помимо указанных в кейсе — главное, чтобы работал ключевой сценарий.
- Минимум — из ответа видно документ и фрагмент; остальное (просмотр документа целиком с переходом по ссылкам, история диалогов, работа с несколькими документами одновременно) необязательно, но может усиливать решение.
- Отдельный сайт делать не требуется, он не оценивается и рассматривается только как дополнение.
- Для допуска достаточно локального запуска через Docker; развёрнутый интерфейс по ссылке можно сделать, но не обязательно.

Внедрение и интеграция
- Разграничение ролей и прав доступа в прототипе не нужно — достаточно одного пользователя.
- Интеграция с Консультант+ не предусмотрена.
